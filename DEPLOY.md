# Развёртывание: Render + Supabase + UptimeRobot

Инструкция под вашу связку: код на GitHub, хостинг — Render, база данных —
Supabase (Postgres), защита от «засыпания» — UptimeRobot.

## Почему код изменился

- **Free-тариф Render использует эфемерную файловую систему** — при каждом
  передеплое (и не только) диск сбрасывается, поэтому локальный файл SQLite
  потерял бы данные. Поэтому база переведена на Supabase (Postgres) — она
  живёт отдельно от сервиса и переживает передеплои.
- **Free-веб-сервис Render «засыпает»** после 15 минут без входящих
  HTTP-запросов и просыпается ~30–60 секунд на следующий запрос. Поэтому в
  бота добавлен маленький HTTP-эндпоинт `/`, отвечающий `OK`, — именно его
  и будет пинговать UptimeRobot.

## Шаг 1. Supabase — строка подключения

1. Откройте свой проект в Supabase → кнопка **Connect** в шапке дашборда.
2. Выберите вкладку **Session pooler** (не Transaction pooler и не Direct
   connection). Это важно: прямое подключение Supabase по умолчанию
   доступно только по IPv6, а бесплатный сервис Render его не
   поддерживает — будет ошибка соединения. Session pooler работает по
   IPv4 и корректно работает с тем, как бот использует подготовленные
   запросы (в отличие от Transaction pooler, который их ломает).
3. Скопируйте строку вида:
   ```
   postgresql://postgres.<ref>:[YOUR-PASSWORD]@aws-<region>.pooler.supabase.com:5432/postgres
   ```
4. Замените `[YOUR-PASSWORD]` на пароль базы данных (задавали при создании
   проекта; забыли — сбросить можно в Project Settings → Database). Если в
   пароле есть спецсимволы (`@ # % !` и т.п.) — их нужно URL-закодировать.

Таблица в базе создастся автоматически при первом запуске бота — руками в
Supabase ничего создавать не нужно.

## Шаг 2. GitHub

```bash
git add .
git commit -m "Переход на Supabase, подготовка к деплою на Render"
git push
```

## Шаг 3. Render — веб-сервис

### Вариант А — вручную
1. **New +** → **Web Service** → подключите репозиторий.
2. Runtime: **Python 3**.
3. Build Command: `pip install -r requirements.txt`
4. Start Command: `python bot.py`
5. Plan: **Free**.
6. Вкладка **Environment** → добавьте переменные:
   - `BOT_TOKEN` — токен от BotFather
   - `WHITELIST` — Telegram ID через запятую
   - `ADMIN_IDS` — Telegram ID администраторов (подмножество WHITELIST,
     через запятую) — только они могут редактировать карточки
   - `DATABASE_URL` — строка из шага 1
7. (Необязательно) В настройках сервиса Health Check Path: `/`.
8. **Create Web Service**, дождитесь деплоя. Скопируйте адрес вида
   `https://ваш-бот.onrender.com`.

### Вариант Б — через render.yaml
В проекте уже есть `render.yaml`. **New +** → **Blueprint** → выберите
репозиторий — Render сам считает конфигурацию из файла и попросит только
заполнить секреты (BOT_TOKEN, WHITELIST, ADMIN_IDS, DATABASE_URL).

## Шаг 4. UptimeRobot

1. **Add New Monitor**.
2. Monitor Type: **HTTP(s)**.
3. URL: корень вашего адреса — `https://ваш-бот.onrender.com/`
   (не `/robots.txt` — этот путь Render отдаёт сам, не «будя» сервис).
4. Interval: **5 минут** (главное — меньше 15, после которых Render
   усыпляет free-сервис).
5. Save.

Этот же `/`-эндпоинт внутри бота дополнительно делает лёгкий запрос к
Supabase — это заодно не даёт приостановиться и самой базе на её
free-тарифе при долгом отсутствии активности.

## Проверка

- Откройте `https://ваш-бот.onrender.com/` в браузере — должно вернуться
  `OK`.
- Напишите боту `/start` в Telegram.

## Если что-то не работает

Вкладка **Logs** в Render покажет вывод бота. Частые причины проблем:
- Неверная строка `DATABASE_URL` (проверьте пароль и что это именно
  Session pooler, порт 5432, а не Direct connection или Transaction
  pooler).
- Пустой `WHITELIST` — бот отвечает отказом всем, включая вас.
- Забыт `BOT_TOKEN` — бот не запустится вовсе (видно в логах при старте).
